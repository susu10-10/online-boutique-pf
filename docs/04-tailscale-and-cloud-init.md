# 04 — Tailscale: The Secret Tunnel

*Or: The 7-Hour Authentication Marathon*

---

## Why Tailscale

Public SSH is a vulnerability. Even with key-only auth, a public SSH port is bombarded by bots seconds after going live. The solution: **eliminate the public attack surface entirely.**

Tailscale creates a WireGuard mesh network. Every device gets a unique IP (`100.x.x.x` range). Services communicate through an encrypted tunnel. No ports exposed to the internet — the tunnel handles authentication.

## The Architecture

```
GitHub Runner → Tailscale tunnel → Droplet (tailscale0 interface)
                                                   ↓
                                              UFW rules:
                                              tailscale0:22 → ALLOW
                                              eth0:22      → DENY
                                              eth0:80/443  → ALLOW (public web)
```

The runner connects to the tailnet via an OAuth client. The droplet joins via an auth key generated by Terraform. Both are authenticated devices. SSH happens through the tunnel — no public IP involved.

## The OAuth Client Setup (Step by Step)

1. Go to https://console.tailscale.com/admin/settings/oauth
2. Click "Create OAuth Client"
3. Set description (e.g., "Terraform Provider")
4. Select scopes:
   - **Devices → Core → Write** (to register devices)
   - **Keys → Auth Keys → Write** (to generate auth keys)
5. In the "Tags" field, add the tag for devices created by this client: `tag:boutique-servers`
6. Click "Generate" and copy the Client ID and Secret

**Critical:** The tag you specify here is the **only** tag this OAuth client can assign. If the Terraform config uses `tags = ["tag:boutique-servers"]` but the OAuth client doesn't have that tag in its allowed list, the auth key creation succeeds but the device can't authenticate. This was our biggest Tailscale bug.

## The Two OAuth Clients

We created two OAuth clients:

| Client | Tag | Used By |
|--------|-----|---------|
| Terraform Provider | `tag:boutique-servers` | `terraform.yml` → generates auth keys for the droplet |
| GH Actions Runner | `tag:ghrunners` | `deploy-reusable.yml` → connects the runner to the tailnet for SSH |

Both are necessary. The Terraform client creates the auth key. The GH Actions client lets the runner join the tailnet and SSH to the droplet.

## The ACL Configuration

Tailscale's ACL (Access Control List) defines who can talk to whom:

```json
{
  "tagOwners": {
    "tag:ghrunners":        [],
    "tag:boutique-servers": [],
  },
  "grants": [
    {
      "src": ["autogroup:member", "tag:ghrunners"],
      "dst": ["tag:boutique-servers"],
      "ip":  ["*"],
    },
  ],
  "ssh": [
    {
      "action": "accept",
      "src": ["susu10-10@github"],
      "dst": ["tag:boutique-servers"],
      "users": ["boutique", "root"],
    },
    {
      "action": "accept",
      "src": ["tag:ghrunners"],
      "dst": ["tag:boutique-servers"],
      "users": ["boutique", "root"],
    },
  ],
}
```

**The Bug:** Originally `tag:boutique-servers` had `"autogroup:admin"` as its owner. This meant every device with this tag required manual admin approval — exactly what we were trying to automate. **Fix:** Changed owner to `[]` (empty), allowing the OAuth client to auto-approve devices.

Also note: `autogroup:member` gives SSH access to all tailnet members. `tag:ghrunners` gives the CI runner access. Both can SSH as `boutique` or `root`.

## Terraform Tailscale Provider

```hcl
provider "tailscale" {
  oauth_client_id     = var.ts_client_id
  oauth_client_secret = var.ts_client_secret
}
```

The provider uses OAuth, not an API key. This is important because OAuth tokens are ephemeral — they expire and auto-renew. API keys are permanent and riskier if leaked.

## The Auth Key

```hcl
resource "tailscale_tailnet_key" "boutique_key" {
  reusable      = true
  ephemeral     = true
  preauthorized = true
  expiry        = 3600
  tags          = ["tag:boutique-servers"]
}
```

**The `reusable` Saga:** This was `false` originally. The idea was "single-use for boot security." But the Terraform key was created during `terraform apply`, and then cloud-init runs a few minutes later. With `reusable = false`, the key was consumed the moment Terraform created it, leaving a dead key for cloud-init. **Fix:** `reusable = true`.

**The `ephemeral` Saga:** This is about cleanup, not auth. `false` means the device registration persists in Tailscale even after the Droplet is destroyed. When you recreate the Droplet with the same name, you get `boutique-droplet-1`, `boutique-droplet-2`, etc. **Fix:** `ephemeral = true` — device auto-removes when it disconnects.

## The Cloud-Init Integration

```yaml
runcmd:
  - curl -fsSL https://tailscale.com/install.sh | sh
  - sh -c 'for i in $(seq 1 15); do systemctl is-active tailscaled >/dev/null 2>&1 && break; sleep 1; done'
  - tailscale up --authkey="${tailscale_authkey}" --ssh --accept-routes --accept-dns=false
```

The `tailscale_authkey` is injected via Terraform's `templatefile()` function, which reads the cloud-init YAML and substitutes `${tailscale_authkey}` with the actual key value before passing it to the droplet.

**The Bug:** `{1..15}` (bash brace expansion) doesn't work in `/bin/sh`. Changed to `$(seq 1 15)` which is portable.

## The Debugging Marathon

The single hardest part of the entire project was getting Tailscale to authenticate automatically. Here are all the things that went wrong:

| Attempt | What Happened | Why |
|---------|--------------|-----|
| `reusable = false` | Key consumed by Terraform, cloud-init gets nothing | Single-use key was used before cloud-init ran |
| `ephemeral = false` | Stale device entries accumulated | Device registration persisted after destroy |
| No tag in OAuth | Key created with tag, but OAuth client couldn't assign it | Scope mismatch |
| `tag:boutique-servers` owned by admin | Device needed manual approval | Tag ownership required approval |
| `systemctl enable --now tailscaled` duplicated | Service failed to start | Install script already does this — race condition |
| Stale TUN device | tailscaled couldn't start | Previous manual `tailscale up` left stale interface |
| `tailscale0` interface not created | UFW rules couldn't find it | Install took longer than expected, rules ran before daemon |

## How to Verify SSH Works

```bash
# Via Tailscale (from your local machine on the tailnet):
ssh -i ~/.ssh/id_do_droplet boutique@boutique-droplet.tail107809.ts.net

# Via public IP (should fail):
ssh -i ~/.ssh/id_do_droplet boutique@<public-ip>
# → Connection timed out

# Check UFW rules on droplet:
sudo ufw status verbose
# → 22/tcp DENY IN on eth0
# → 22/tcp ALLOW IN on tailscale0
```
